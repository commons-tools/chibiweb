# 手順書：お客さんのサイトを作って納品するまで

chibiwebで、お客さん（小さなお店や団体）のサイトを作って渡すまでの手順です。
この手順書があれば、だれが作っても同じものができる。作った人が替わっても、続きを引き受けられる。そのための1枚です。

考え方（なぜこう作るのか）は [FOR-MAKERS.md](FOR-MAKERS.md) に、デザインのルールは [DESIGN.md](DESIGN.md) にあります。この手順書は「何を、どの順番で」だけを書きます。

---

## 0. この手順書の前提

- 作るのは、**店舗案内・地図・お知らせ**が中心の小さなサイト。毎日の写真や商品は、お店のInstagramに任せる
- サイトは、作る人のドメインの下の**サブドメイン**に置く（例：`https://お店の名前.あなたのドメイン/`）
- 作る人は、PHP 8.1 以上が動くレンタルサーバーを持っている
- AIと話しながら作業する。AIには `public/` の中身と `docs/` のmdを一緒に渡す

### かかる時間の目安

原稿と写真がそろっていれば、**作業は合わせて8時間くらい**。ただし、原稿や写真が届くのを待つ時間と、修正のやりとりがあるので、**完成までの日数は2〜3週間**とみておく。

| 手順 | 作業時間の目安 |
|---|---|
| 1. 最初に決めること | 0.5時間 |
| 2. ヒアリングと原稿集め | 1.5時間 |
| 3. サーバーの準備 | 0.5時間 |
| 4. 設定とアップロード | 0.5時間 |
| 5. デザイン | 1時間 |
| 6. ヘッダー・フッター・メニュー | 0.5時間 |
| 7. ページの中身 | 2.5時間 |
| 8. 確認 | 0.5時間 |
| 9. 納品 | 0.5時間 |

---

## 1. 最初に決めること

作業を始める前に、お客さんと次のことを決めて、文字に残す（メールやLINEでよい）。

- [ ] **作るページ**：ホーム、お店について、お知らせ一覧。必要なら、サービス一覧などを1〜2ページ
- [ ] **作らないもの**：通販、予約、会員機能、商品の写真の一覧（Instagramに任せる）
- [ ] **原稿と写真はお店側で用意する**：文章を整えるのは作る人が手伝う
- [ ] **修正は2回まで**：それ以上は別料金
- [ ] **サイトの住所（URL）は、作る人のドメインの中にある**こと。いつでも独自ドメインに移せること
- [ ] **サイトの寿命は3年**とみて、3年たったら作り直しを相談すること（FOR-MAKERS 7章）
- [ ] **納品後の更新**をどうするか：お知らせはお店の人が自分で書く。それ以外の更新は、代行するかどうか

## 2. ヒアリングと原稿集め

### 集めるもの

- [ ] お店の名前（日本語と、フッター用の英語表記）
- [ ] お店のひとこと（どんな店か。2〜3行）
- [ ] 営業時間、定休日
- [ ] 住所、Googleマップで表示する場所
- [ ] 電話番号、メールアドレス（載せるかどうかも確かめる）
- [ ] InstagramなどSNSのアカウント
- [ ] メイン写真1枚（横長。お店の雰囲気がわかるもの）
- [ ] 下層ページの原稿と写真
- [ ] お知らせの種類（ふつうのお知らせ、臨時休業、イベントや教室など）
- [ ] デザインの好み（好きな色、参考にしたいサイト）

### `CONTENT.md` に書く

集めたことは、まず `docs/CONTENT.md` に書く。ページ一覧、各ページの役目、文章のトーン。**ここが、このサイトの決まりごとの置き場所になる**。

### ページごとの原稿メモ

新しいページ（サービス一覧など）を作るときは、AIに渡す**原稿メモ**をmdで書く。置き場所は `docs/`（例：`docs/memo-service.md`）。サーバーには上げない。

```markdown
# 原稿メモ：サービスのご案内（service.html）

## このページの役目
はじめての人が、メニューと値段と所要時間を知って、予約の電話をかけられるようにする

## 見出し
- 小さい1行目：Service
- 大きい本題：サービスのご案内
- リード文：はじめての方は、カウンセリングつきのコースがおすすめです。

## 本文
### カット
- カット　4,400円　約60分
- 前髪カット　1,100円　約15分

### カラー
（以下、同じように）

## 写真
- photos/service-color.jpg：カラーの見出しの下に1枚

## 最後に
予約は電話で。営業時間と電話番号を、ページの最後にもう一度
```

## 3. サーバーの準備

- [ ] レンタルサーバーの管理画面で、**サブドメインを作る**
- [ ] そのサブドメインの**無料SSLをオンにする**（反映まで数十分〜1時間かかることがある）
- [ ] `https://` で開けることを確かめる

## 4. 設定とアップロード

- [ ] chibiwebの最新版を GitHub から持ってくる
- [ ] `public/news/config.php` を直す
  - `setup_key`：合言葉。推測されにくいものに（[SECURITY.md](SECURITY.md) 参照）
  - `site_name`：お店の名前（管理画面に出る）
  - `channels`：お知らせの種類。見本の「パン教室」は、お店に合わせて名前を変えるか消す
- [ ] 見本のお知らせを消す：`public/news/data/` の中の、こむぎ舎の `.md` ファイル
- [ ] `public/` の**中身**を、サブドメインのフォルダにアップロードする（`public` フォルダごとではない）
- [ ] `https://サブドメイン/news/admin/` を開き、合言葉とパスワードを入れる。**パスワードは、できればお客さん本人にその場で決めてもらう**

## 5. デザイン

- [ ] お客さんの好みを、`docs/DESIGN.md` の言葉で書き足す（色、文字の雰囲気）
- [ ] AIに `DESIGN.md` を読ませて、`public/assets/style.css` の**先頭の変数だけ**を直してもらう
- [ ] 文字と背景の色の差が十分か（読みやすいか）を確かめる

くわしくは [FOR-DESIGNERS.md](FOR-DESIGNERS.md) へ。

## 6. ヘッダー・フッター・メニュー

直すのは `public/site.json` の1か所だけ。全ページに反映される。

- [ ] `name`：お店の名前
- [ ] `logo`：ロゴ画像があればそのパス。なければ空のまま（文字で出る）
- [ ] `menu`：ページの一覧。ページを足したら、ここにも足す
- [ ] `copyright`：フッターに出す英語の名前（`Copyright © 年 名前` になる）

## 7. ページの中身

AIと話しながら、上から順に直す。直す前に、AIに `AGENTS.md` を読ませる。

- [ ] **メイン写真**：元の写真を `photos/` に置き、AIに3サイズ（800・1600・2400px）のWebPにしてもらう。大事なものが中央の帯に入っているか確かめる
- [ ] **ホーム**：お店のひとこと → 営業時間 → アクセス（住所と地図）の順。並びはFOR-MAKERS 4章の「来店までの順番」
- [ ] **地図**：Googleマップの埋め込みを、ホームのアクセス欄に入れる
- [ ] **お店について**（`about.html`）
- [ ] **新しいページ**：原稿メモを渡して、`about.html` をコピーして作ってもらう。できたら `CONTENT.md` のページ一覧に1行足す
- [ ] **お知らせの最初の1件**：「サイトを公開しました」など、空っぽにしない
- [ ] 見本の文章（こむぎ舎）が残っていないか、ページを全部見て確かめる

## 8. 確認

- [ ] **スマホで全ページを見る**：文字の大きさ、写真の切れ方、表のはみ出し
- [ ] メニューが開いて、全ページに行ける
- [ ] 地図が表示される
- [ ] 電話番号を押すと電話がかかる（載せている場合）
- [ ] お知らせを1件書いて、ページに出ることを確かめる
- [ ] 臨時休業のお知らせを書いて、ホームのいちばん上に出ることを確かめる。確かめたら消す
- [ ] `https://サブドメイン/news/data/` を開いて、**中身が見えない**（拒否される）ことを確かめる
- [ ] 見本の文章、「要確認」、仮の数字が残っていない

## 9. 納品

- [ ] **管理画面の使い方を教える**（30分くらい）。お客さんのスマホで、実際に1件書いてもらう
  - お知らせの書き方、下書き、日付を未来にすると予約公開
  - 臨時休業は「緊急のお知らせ」に書く。**過ぎたら消すか下書きに戻す**（残っているとホームの上に出続ける）
  - パスワードアプリに保存してもらう
- [ ] **引き継ぎのメモを渡す**（下のひな形）
- [ ] 作業したファイル一式（`public/` と `docs/`）を、手元とGitHubなどに残しておく

### 引き継ぎのメモ（ひな形）

```markdown
# ○○（お店の名前）のホームページについて

- サイトの住所：https://○○.example.com/
- お知らせを書く画面：https://○○.example.com/news/admin/
- サイトのファイルの置き場所：○○サーバー（作った人が管理）
- 作った人：○○　連絡先：○○
- 公開した日：2026年○月○日

## ほかの人に頼みたくなったら
サイトのファイル一式（public フォルダと docs フォルダ）を渡してください。
docs の中の説明書を読めば、だれでも続きを引き受けられます。

## 自分のドメインを持ちたくなったら
作った人に連絡してください。いつでも移せます。

## 3年たったら
そのときの技術で、作り直しを相談しましょう。お知らせや文章は、そのまま持っていけます。
```

---

## 納品のあとに

### 更新を代行するとき

- お知らせ以外の更新（営業時間、メニュー、写真の入れ替え）を頼まれたら、この手順書の5〜8を、変わるところだけ行う
- 「これからもこうする」と決めたことは、`CONTENT.md` や `DESIGN.md` に書き戻す（FOR-MAKERS 11章）

### 年に1回の点検

- [ ] サーバーのPHPのバージョン
- [ ] ドメインとSSLの更新日
- [ ] `news/data/` のバックアップ
- [ ] リンク切れ、古くなった情報（値段、営業時間）
- [ ] 終わった臨時休業のお知らせが残っていないか
